## What I Ended Up With
A web page that lists every drive in my server with a clear pass or fail, its temperature, and the history of the S.M.A.R.T. attributes that matter. If a drive starts reporting problems, I get a notification instead of finding out when files go missing.

## Why I Chose Scrutiny

Drives usually give warning signs before they fail, but nobody runs `smartctl` by hand every week. Scrutiny does it on a schedule, keeps the history, and combines the manufacturer's thresholds with real-world failure rates to judge which numbers matter.

## How I Set It Up

### 1. Finding the Drives
I ran `smartctl --scan` on the host to get the list of devices.

### 2. The Container
I used the omnibus image, which bundles the web interface and the collector. Following the README, I passed each drive in as a device, added the capabilities it needs (one more for NVMe drives), and mounted the udev folder read-only.

### 3. Checking and Alerts
I opened the web interface, confirmed every drive was listed with data, and set up a notification so a failing drive reaches me.
